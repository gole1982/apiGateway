# 初次配置指南（v2 · 中心角色自动判定 + 指标仪表盘）

> 本指南面向 2026-09 重大更新后的首次部署。涵盖：Supabase 中心搭建、**管理端 UI 录入 key 自动判定角色**（替代手改 proxy.cfg）、代理端配置、独立模式、新功能速览。
>
> 基础搭建步骤（建 Supabase 项目、跑 schema）与 [日常操作手册 · 五](日常操作手册.md) 一致，本指南只补充增量与过时部分的更正。

---

## 一、三种运行角色

程序同一份二进制，按"是否连中心 + key 权限"分三种角色，**角色现在由录入的 API key 权限自动判定**，不再依赖配置文件段名：

| 角色 | 触发条件 | 行为 |
|------|---------|------|
| **管理端** | secret key（`sb_secret_...`，旧称 service_role）对定义表可写 | 面板增删改**直写中心 Supabase**，写后即时拉回本地镜像；所有代理节点 60s 内自动拉取 |
| **代理端** | publishable key（`sb_publishable_...`，旧称 anon）只读 | 定时轮询中心版本号，变了全量拉取应用；定义类写被只读守卫拦截，提示"请在管理端修改" |
| **独立模式** | 未连中心（无 key / 连接失败） | 纯本地 SQLite 配置，所有操作读写本地，不与中心交互 |

> **key 在哪获取**：Supabase Dashboard → 你的项目 → **Settings > API Keys**（页面路径 `/dashboard/project/_/settings/api-keys/`）。两把 key 都在同一页：`sb_publishable_...`（publishable，可放代理端/前端）和 `sb_secret_...`（secret，仅放管理机、绝不外泄）。旧名 `anon` / `service_role` 2026 年底弃用，新名等价。

判定方式：程序启动时（或面板"中心配置"页点"重新探测"时）依次发 `GET /rest/v1/rpc/get_version`（探连通）+ `PATCH /rest/v1/platform?id=eq.-1`（探写权限，0 行受影响、无副作用）→ 200/204=管理端，401/403=代理端，连不上=未连接。

## 二、第 1 次搭建（只做一次）

### 1. 建 Supabase 中心库

去 [supabase.com](https://supabase.com) 注册 → New project → 在 **Settings > API Keys** 拿到（路径 `/dashboard/project/_/settings/api-keys/`）：
- **项目 URL**：`https://你的项目.supabase.co`
- **secret key**（`sb_secret_...`，旧称 service_role）—— 管理端用，可写全表，**只放你自己的管理机**
- **publishable key**（`sb_publishable_...`，旧称 anon）—— 代理端用，只读

在 Supabase 的 **SQL Editor** 跑项目里的 [`scripts/supabase_schema.sql`](../scripts/supabase_schema.sql) —— 建定义表（platform / platform_keys / rapi / lapi / lapi_rapi_order）+ 版本号 `config_meta.version` + 增删改自动 +1 的触发器 + `get_version()` / `get_bundle()` 两个拉取 RPC。幂等，可重复跑。

可选：跑 [`scripts/supabase_seed_example.sql`](../scripts/supabase_seed_example.sql) 录入示例配置（一段一个平台 + 它的 key + 模型）。

### 2.（可选）生成 token 加密密钥（center_key）

**默认不需要**：中心侧访问安全由 Supabase 负责（RLS + API key），token 在中心库存明文即可。
仅在「多代理共享中心、且担心 publishable key 泄露后被拖库读 token」时才需要这层应用层加密。

需要时生成 32 字节随机 hex，管理端与所有代理端**必须同一串**（管理端用它加密 token 写入中心，代理端用它解密）：

```bash
openssl rand -hex 32
# 或 python: python -c "import secrets;print(secrets.token_hex(32))"
```

不配 center_key 则所有端留空即可（留空 = 中心存明文）。

## 三、管理端配置（你自己的电脑，只需一台）

> **新流程**：不再手改 `proxy.cfg`，改在面板「中心配置」页录入 URL + key，系统加密保存并自动判定角色。

### 方式 A：面板录入（推荐）

1. 编译并启动：
   ```bash
   go build -o gateway.exe ./cmd/gateway/
   ./gateway.exe
   ```
2. 浏览器打开控制台 `http://127.0.0.1:43211`（端口见 `proxy.cfg` 的 `web_port`）。
3. 左侧导航点「**中心配置**」。
4. 填 Supabase 项目 URL + secret key（`sb_secret_...`） → 点「保存并探测」。
5. 系统用本机密钥 AES 加密 key 存入本地 SQLite `settings` 表（不明文落盘），并即时探测权限：
   - 显示「**管理端（可写）**」绿色徽章 = 成功；
   - 显示「代理端（只读）」= 你填了 publishable key（`sb_publishable_...`），换成 secret key；
   - 显示「未连接」= URL/key 错或网络不通，看页面错误提示。
6. 保存即**热激活**，无需重启（center_key 也在同一表单录入，留空=沿用已保存值）。激活后面板顶栏 ☁ 图标显示连通状态，日志出现 `[MGMT] management mode hot-activated`。

### 方式 B：proxy.cfg 回退（无头/自动部署）

面板录入是优先方式；若需脚本化部署，`proxy.cfg` 仍支持：

```ini
[management]
supabase_url = https://你的项目.supabase.co
service_key = 你的 secret key（sb_secret_...）  ; 仅管理机，绝不外泄
center_key = 第二节生成的32字节hex
```

启动后 `[MGMT] management mode` 日志即生效。`settings` 表配置优先于 `proxy.cfg`。

### 管理端能做什么

- 顶栏「＋新增」向导：平台 → 密钥 → 模型 → 测试 → 保存，**直写中心**。
- 平台/密钥/模型/接口四个管理 tab 的增删改全部直写中心，版本号自动 +1。
- 删除等危险操作的确认弹框会追加「⚠ 管理模式：此操作将直写 Supabase 中心库，并同步影响所有代理节点」提示。

## 四、代理端配置（每台转发机器）

代理端定时轮询拉取中心定义。`proxy.cfg` 加：

```ini
[sync]
source_url = https://你的项目.supabase.co/rest/v1/rpc/get_bundle
version_url = https://你的项目.supabase.co/rest/v1/rpc/get_version
anon_key = 你的 publishable key（sb_publishable_...）  ; 只读公钥，可放转发机
center_key = 第二节生成的32字节hex  ; 解密 token 用，与管理端同一串
poll_interval_sec = 60
```

启动日志 `[SYNC] enabled` 即生效。中心或网络挂了沿用本地缓存继续转发（fail-open），面板 ☁ 图标变红显示"中心离线"。

### 代理可本地写 + 软拉取（应急场景）

代理角色也能在面板增删改定义（应急改本地 SQLite，**不推中心**）。为避免应急改被中心更新自动覆盖，面板「中心配置」页提供**拉取模式**切换：

- **自动（默认）**：每 60s 轮询，中心有新版本自动应用到本地（现状行为）。
- **手动**：轮询只记"中心有更新待拉取"，**不应用**，本地应急改保留。需要时点「⬇ 从中心拉取到本地」手动应用——会覆盖本地应急改。

API：`GET/POST /api/sync/pull-mode`（mode=auto|manual）；手动拉取调 `POST /api/sync/refresh`。

典型用法：出差时在代理机临时改个 key/模型，切手动模式保留；回到管理端正式录入后，代理机切回自动或手动拉取同步。

## 五、独立模式（单机、不连中心）

不配 `[management]` 也不配 `[sync]`、不在面板录入 key → 纯本地 SQLite，所有操作读写本地。适合只在一台机器跑、不需要多机同步的场景。面板「中心配置」页显示「未连接」。

## 六、启动验证

```bash
go build -o gateway.exe ./cmd/gateway/ && ./gateway.exe
```

正常启动日志含：
- `proxy server starting` addr=`0.0.0.0:43210`（代理端口）
- `web dashboard starting` addr=`127.0.0.1:43211`（控制台端口）
- 管理端：`[MGMT] management mode: definitions write through to center`
- 代理端：`[SYNC] enabled`
- 独立模式：`[SYNC] disabled (no [sync] source_url), running standalone`

浏览器开 `http://127.0.0.1:43211`，左侧导航应无滚动完整显示 8 项（仪表盘 / 平台 / 密钥 / 模型 / 接口 / 日志 / 中心配置 / Playground）。仪表盘首屏一屏内可见：KPI 概览（总请求/成功率/延迟/429/5xx）+ 指标矩阵 + 待处理 + 近期错误。

## 七、新功能速览

### 1. 仪表盘指标矩阵（今日/本月切换）

仪表盘顶部「今日 | 本月」切换。4 维度（平台 / Key / 模型 / 接口）× 10 指标各取 TOP3：

- 最多总 token / 输入 token / 命中缓存 token / 输出 token
- 最多尝试访问 / 最多报错
- 首 token 延迟最低/最高、除首 token 平均延迟最低/最高

数据来自 `request_logs`（token 明细 / TTFT / 使用的 key 自本次更新起埋点；历史请求该字段为 0，显示"—"，从上线起累计）。聚合接口 `GET /api/dashboard/metrics?period=today|month`。

### 2. 中心配置页（侧栏「中心配置」）

显示当前角色徽章、连通性、5 张中心表行数。录入/更换 key 即重探测。proxy.cfg 仍作无头回退。

### 3. 系统/中心互联日志

日志监控页顶部「系统/中心互联日志」折叠卡片：记录 syncOnce 成败、版本应用、直写成败等。接口 `GET /api/logs/system`。中心离线/待同步也进仪表盘待处理区与顶栏铃铛。

### 4. 多 Key 轮询 + 429 池标准冷却

同平台多 key 改为**一般轮询**（不再偏向免费/临期 key），均匀分摊配额。全部 key 进入 429 后，以**第一个进 429 的 key 的恢复时刻**为池标准对齐整池与 RAPI 冷却，期间 `PickAvailable` 直接走链上下一节点，消除"RAPI 短冷却到期→key 仍冷却→空转循环→请求干等 120s"的旧行为。池耗尽事件写入请求日志，日志页可见。

### 5. 确认提示 sb 提醒

管理模式下所有删除/重置确认弹框追加「⚠ 此操作将直写中心库，并同步影响所有代理节点」。

## 八、常见问题

**Q：面板显示「未连接」？**
检查 Supabase 项目是否暂停（免费档 7 天不活跃会暂停，登录控制台唤醒）、URL 是否带 `https://`、key 是否粘贴完整。点「重新探测」看错误提示。

**Q：角色探测显示「代理端（只读）」但我想要管理端？**
你填的是 publishable key（`sb_publishable_...`，只读）。换成 secret key（`sb_secret_...`，可写）——Supabase Dashboard → Settings > API Keys 同一页拿。

**Q：指标矩阵 platform/key 列今日为空？**
platform/key 维度依赖本次更新新增的埋点列（`selected_key_id`/`selected_platform_id`），历史请求该列为 0 被过滤。自更新上线后的新请求才会出现；本月维度里模型/接口列用旧字段（别名），有历史数据。

**Q：改了 key 后多久生效？**
面板录入即时探测角色并**热激活**（management→直写中心；proxy→只读同步），无需重启。配置（URL/key/center_key）加密存本地 settings 表，`proxy.cfg` 仅作无头启动回退。

**Q：管理端和代理端能同一台机器吗？**
不推荐。管理机配 `[management]`（或面板录入），转发机配 `[sync]`；同一台二选一，别同时配两种角色。

**Q：token 在中心库是明文吗？**
默认是——中心侧访问安全由 Supabase（RLS + API key）负责。若配置了 `center_key`（可选），管理端用它（AES-256-GCM）加密后写入中心、代理端用同一把 key 解密；此时 center_key 为 32 字节 hex，管理端与代理端必须一致。

## 附：端口与配置文件

`proxy.cfg`（与本二进制同目录）：

```ini
proxy_port = 43210      ; 代理转发端口（客户端调这里）
web_port = 43211        ; 控制台端口（浏览器开这里）

; 以下三选一：
; [management]  管理端（或面板「中心配置」页录入，优先）
; [sync]        代理端（只读拉取）
; 都不配        独立模式
```

数据库：本地 SQLite `gateway.db`（定义表 + request_logs + rapi_metrics + settings + system_logs）。
